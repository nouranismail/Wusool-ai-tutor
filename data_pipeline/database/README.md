# Educational AI Tutor — PostgreSQL + pgvector

This package contains the six validated textbook JSON outputs and a database
import pipeline built against their inspected JSON structure.

## Included corpus

- 6 textbooks
- 554 page records
- 1,291 chunks
- Source PDFs are intentionally not copied into this package to keep it small.
- Only each book's current `output/pages.json`, `output/chunks.json`, and
  `output/validation_report.json` are included. Old nested output folders are excluded.

## Requirements

- Python 3.10+
- PostgreSQL 15+ (or a compatible recent version)
- pgvector extension installed on the PostgreSQL server

## Setup

1. Create a database named `educational_tutor`.
2. Install pgvector for your PostgreSQL installation.
3. From this project directory:

   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # macOS/Linux:
   source .venv/bin/activate

   pip install -r requirements.txt
   copy .env.example .env
   ```

4. Edit `.env` and set your PostgreSQL password.
5. Apply the schema:

   ```bash
   psql -U postgres -d educational_tutor -f database/schema.sql
   ```

6. Import the six books:

   ```bash
   python database/importer.py
   ```

7. Validate the imported data:

   ```bash
   python database/validate_db.py
   ```

Run commands from the project root. If using PowerShell, `copy .env.example .env`
works; otherwise use `Copy-Item .env.example .env`.

## Import behavior

The importer reads the actual corpus format:
- `pages.json`: top-level JSON array of page objects
- `chunks.json`: top-level JSON array of objects with `chunk_id`, `text`,
  and `metadata`
- chunk-to-page relation: `metadata.pdf_page_index`

Re-importing a book replaces that book's pages in a single transaction. Cascading
foreign keys remove its previous chunks and embeddings before the current snapshot
is inserted. Do not run two imports concurrently against the same book.
**Re-importing a book also deletes that book's embeddings** (cascade), so run
`python embeddings/generate_embeddings.py` again afterwards.

All pages are stored, including pages where `include_in_rag=false`. The retrieval
query filters those pages out.

## Embeddings

Embedding generation is intentionally a separate step. First import and validate
the corpus. Then benchmark multilingual embedding models on representative Arabic
and English questions. The included starter uses `intfloat/multilingual-e5-base`;
for E5, query text should use the `query: ` prefix and stored passages use
`passage: `. The starter script handles passage prefixes. Build a query encoder
with the matching `query: ` prefix before using semantic search.

The `vector` column is dimensionless until the model is chosen. After benchmarking,
you can create a dimension-specific HNSW index. For example, only if the chosen
model outputs 768 dimensions:

```sql
CREATE INDEX IF NOT EXISTS idx_chunk_embeddings_e5_base_hnsw
ON chunk_embeddings
USING hnsw ((embedding::vector(768)) vector_cosine_ops)
WHERE embedding_model = 'intfloat/multilingual-e5-base';
```

Because the column is dimensionless, the index is built on a cast expression.
To make PostgreSQL use it, the search query must filter on the same
`embedding_model` and order by `(e.embedding::vector(768)) <=> %s`.

For production, create the ANN index only after confirming the selected model's
vector dimension and the pgvector version's index requirements. Do not mix
vectors from different models in one similarity comparison.

`semantic_search.py` casts the column to `vector(EMBEDDING_DIM)` (default 768,
set in `.env`) so the HNSW expression index above is actually used.
Change `EMBEDDING_DIM` if you pick a model with a different output size.

## Important notes

- The importer preserves original page/chunk IDs and metadata.
- It does not modify the original OCR, chunking, or validation scripts.
- The JSON corpus is a snapshot; if you regenerate chunks later, re-import.
- Check OCR uncertainty and source-page notes before relying on affected passages.
- `semantic_search.py` expects a query vector generated by the same embedding
  model and normalization convention as the stored vectors.
  Use `search_text("your question", subject="Science", grade=4)` to encode the
  question with the correct `query: ` prefix automatically.
